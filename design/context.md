# 里程碑功能设计上下文

## Goal

把单一的“比赛倒计时”升级为可管理的通用里程碑，让考试、旅行、纪念日、生活安排、学习、比赛和项目节点共用一条时间轨道。

## User

- 工科大学生，正在学习嵌入式开发。
- 对机械设计、SolidWorks、Blender 与 3D 打印有实践兴趣。
- 计划参加电赛、嵌入式与睿抗类工程竞赛。
- 长期研究方向为低空经济与无人机。

## Job to be done

需要在 30 秒内记录一个重要事件，并在总览与月历中快速回答三个问题：最近要发生什么、还有多久、是否需要关联某个项目。

## Product boundary

- 里程碑：考试、出发日期、纪念日、报名截止、比赛、交付、答辩等跨天的重要事件。
- 今日计划：今天能实际执行和勾选的学习、设计、编码、装配或测试动作。
- 一个里程碑可以独立存在，也可以关联项目，但不会自动生成今日计划，避免职责重叠。

## Constraints

- React + TypeScript 的现有本地工作台。
- 无后端，使用 localStorage 持久化。
- 延续黑、白、灰、黄色的工业标尺视觉语言。
- 不引入圆角 SaaS 卡片、玻璃拟态或独立第三方日历。

## V1 scope

- 新增、编辑、删除里程碑。
- 完成与恢复里程碑。
- 名称、日期、时间、类型、优先级、备注、可选关联项目。
- 总览显示最近节点倒计时和后续节点序列。
- 可展开查看全部事件，并恢复较早的已完成事件。
- 月历与当日议程同步显示里程碑。
- 输入校验与刷新后数据保留。

## Non-goals

- 重复事件与复杂周期规则。
- 系统通知、邮件提醒与自动化。
- 云同步、多人协作、权限体系。

## Success criteria

- 用户能在 30 秒内完成首次创建。
- 新建或修改后，总览与日历立即一致。
- 刷新页面后数据仍然存在。
- 逾期、今日、未来与完成状态可一眼区分。
- 桌面与 720–768px 窄屏无横向溢出。

## Assumptions and risks

- 初始里程碑为空，不虚构用户真实比赛日期。
- 最大风险是和今日计划职责重叠；所有文案和视觉均强调“重要日期/结果节点”而非“今天要做的待办”。
